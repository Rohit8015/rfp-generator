# RFP Copilot v2

A four-plane, thirteen-agent system that turns an RFP into a complete proposal package —
narrative, tables, charts, costings and a compliance matrix — with **provenance on every
sentence**, evidence gaps surfaced rather than written around, and the arithmetic checked.

```powershell
python -m src.orchestrator "data/incoming/RFP-A_questionnaire_nbfc.md"
streamlit run app/dashboard.py
```

## What it actually does

1. **Reads the RFP** and types every requirement — six types, three priorities, and the
   form each answer will take
2. **Recommends bid / partner / no-bid** with the driving factors named
3. **Says what you can prove** — STRONG / PARTIAL / **GAP** per requirement
4. **Drafts each section** in parallel, attributing every sentence to its source
5. **Checks its own work** — arithmetic, requirement coverage, unsupported claims,
   unbounded commitments — and re-drafts failures with the reason fed back
6. **Exports** docx + charts + compliance matrix + an automation report

The honest framing: this does not produce a submittable proposal. It produces a strong
first draft with every claim traceable and every gap flagged. The compliance matrix and
the GAP list are arguably worth more than the prose.

| Priority accuracy | 100% | ≥85% |

| Requirement coverage in outline | 100% | 100% |
| Grounding precision / recall / FPR | 0.909 / 1.000 / 0.100 | >0.80 / >0.80 / <0.10 |
| Adversarial defects caught | 5 of 5 | all |
| Consistency contradictions | 0 | 0 |
| End-to-end runtime (live) | ~126s | <20 min |
| Automation rate — sentences | 65.9% | — |
| Automation rate — sections | 0.0% | ≥65% |

**Read the caveats.** Three matter:

- **RFP-A labels its own requirements** as `**R-001**`, so extraction scores are
  flattered. Read 100% as "this document is easy", not "extraction is solved".
- **The hybrid-beats-dense retrieval gate is untestable here** — dense alone answers 49
  of 50 queries, so no method has 10 points of headroom.
- **The section-level automation rate is 0% and that is correct.** A section counts as
  automated only if no sentence needed a human, and nearly every section carries at
  least one carved-out requirement. The sentence-level figure (65.9%) is what
  distinguishes a mostly-drafted document from a barely-started one.

RFP-D and RFP-E are **sealed** and were never opened.

## Architecture

```
PLANE 1 COMPREHENSION   A1 Structurer · A2 Requirements · A3 Buyer Intel · A4 Qualifier
PLANE 2 STRATEGY        A5 Win Themes · A6 Architect · A7 Proof Matcher
PLANE 3 GENERATION      A8 Hybrid Retriever · A9 Router → 5 writers
PLANE 4 ASSURANCE       A10 Consistency · A11 Compliance · A12 Grounding · A13 Voice/Risk
                        ↑ fail → redraft with the reason, max 2, then escalate
WORKFLOW                W1 Router · W2 Tracker · W3 Assembler
```

**Roughly 40% is deterministic Python** — costing, charts, consistency, compliance,
boilerplate, bid qualification. That is what makes the automation claim defensible
rather than "we asked a model and it agreed".

Rules enforced structurally, not by convention:

- Compliance, legal and unevidenced requirements are **carved out before any model call**
- A `ProvenanceRecord` cannot exist without sources matching its kind
- A `ContextPack` cannot carry a reuse decision without naming its calibration
- A win theme threading fewer than two requirements cannot be constructed
- A GAP cannot cite proof

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # then add at least one key
```

| Provider | Key |
|---|---|
| Groq | https://console.groq.com/keys |
| Gemini | https://aistudio.google.com/apikey |
| HuggingFace | https://huggingface.co/settings/tokens |

All three is best — the chain fails over on rate limits, and pooling three free tiers is
what makes a live run survivable.

Then build the indices (once):

```powershell
python -m src.ingestion.ingest      # 247 chunks → Chroma + BM25
python -m src.ingestion.calibrate   # retrieval thresholds, never hardcoded
```

**Offline path.** Install [Ollama](https://ollama.com), `ollama pull qwen2.5:3b-instruct`,
set `LLM_PROVIDER_CHAIN=ollama`. Runs with no network and no keys, at ~5.7 tok/s.

Embeddings and reranking are **always local** (`bge-small`, `ms-marco-MiniLM`) — cloud
embedding would exhaust free-tier limits in a single ingest.

## Why not local generation

The plan assumed 8–15 tok/s for a local 7B. Measured on the build machine (7.7 GB RAM,
integrated GPU):

| Model | Throughput |
|---|---|
| `qwen2.5:7b-instruct` | **0.15 tok/s** — 68 tokens took 452s |
| `qwen2.5:3b-instruct` | 5.7 tok/s |
| Free-tier cloud | ~1.2s per call |

Generation moved to pooled free-tier cloud. The architecture did not change: every call
still goes through `src/llm/provider.py`, and the pipeline still runs end to end on
Ollama alone.

## Layout

src/writers/      5 writers       src/workflow/     W1–W3

data/eval/sealed/ RFP-D, RFP-E — never opened

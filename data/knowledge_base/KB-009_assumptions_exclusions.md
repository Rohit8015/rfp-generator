# Standard Assumptions & Exclusions

## Proposal Assumptions

### Commercial Assumptions
1. **Pricing Validity**: Pricing valid for 90 days from proposal date
2. **Taxes**: GST (18%) extra as applicable
3. **Exchange Rates**: INR/USD rate of ₹83 fixed for 90 days
4. **Inflation**: Price adjustments allowed for contracts >12 months
5. **Travel**: Client to reimburse travel at actuals (where applicable)
6. **Billing**: Monthly invoices with 30-day payment terms

### Technical Assumptions
1. **Infrastructure**: Client provides necessary hardware, network, and cloud resources
2. **Access**: Client provides timely access to stakeholders, systems, and data
3. **Integration**: Client APIs/systems are available as per the agreed schedule
4. **Data Quality**: Client data is accurate and complete for migration
5. **Security**: Client security policies are compatible with our approach
6. **Change Management**: Client is committed to the change management program

### Project Assumptions
1. **Scope**: Work is limited to the scope defined in the SOW
2. **Timeline**: Based on client's ability to provide inputs on time
3. **Governance**: Joint steering committee will guide the program
4. **Decision-Making**: Client decisions within the agreed SLA (e.g., 5 days)
5. **Team Stability**: Key resources allocated for the project duration
6. **Scope Change**: Changes will be managed through change control

### Regulatory Assumptions
1. **Compliance**: Client is compliant with applicable regulations
2. **Licenses**: Client has all necessary licenses (where applicable)
3. **Data Privacy**: Client has consent for data processing
4. **Legal**: Client legal team to review all agreements and SOWs
5. **Export Control**: No export-controlled data involved (unless specified)

## Standard Exclusions

### Scope Exclusions
1. **Hardware**: Provisioning of hardware is excluded unless explicitly stated
2. **Software Licenses**: COTS licenses are excluded unless explicitly stated
3. **Datacenter**: Datacenter hosting is excluded (cloud/on-prem separate)
4. **Third-Party Integration**: Beyond scope of defined integrations
5. **Training**: Limited to defined number of sessions and participants
6. **Hyper-care**: Limited to defined duration (typically 30-90 days)

### Commercial Exclusions
1. **Travel**: Not included unless stated in the SOW
2. **Accommodation**: Not included unless stated
3. **Visas/Work Permits**: Not included
4. **Insurance**: Not included (client to maintain their own)
5. **Legal Fees**: Not included (separate engagement)

### Technical Exclusions
1. **Data Migration**: Only for systems and data identified in scope
2. **Customization**: Limited to what is defined in the scope
3. **Decommissioning**: Legacy system sunset separate
4. **Training**: Post-project refresher training excluded
5. **Support**: Post-stabilization AMC separate
6. **Enhancements**: Post-go-live enhancements separate

### Risk Exclusions
1. **External Factors**: Pandemics, natural disasters, political instability
2. **Regulatory Changes**: Substantive regulatory changes out of scope
3. **Client Decisions**: Delays from client decision-making
4. **Scope Creep**: Unapproved scope changes
5. **Third-Party Failures**: Delays from third-party dependencies

## Key Assumptions for Major Archetypes

### Financial Services (NBFC/Bank)
**Assumptions**:
- RBI regulations are known and stable
- Client has regulatory approvals for digital lending
- Existing core banking system is accessible
- Client has KYC/AML processes in place

**Exclusions**:
- RBI licensing and approvals
- Core banking system replacement
- Regulatory reporting beyond scope
- Hardware provisioning for DC/DR

### Healthcare
**Assumptions**:
- HIPAA/DPDP compliance framework in place
- Clinical processes are standardized
- Integration with existing HIS/EHR systems
- Patient data quality is acceptable

**Exclusions**:
- HIPAA certification (client responsibility)
- Medical devices integration
- Clinical workflow redesign
- Medical coding and billing changes

### Government/Smart City
**Assumptions**:
- Government approvals and clearances are in place
- Integration with legacy government systems is feasible
- Data sharing agreements are in place
- Security clearances for team members

**Exclusions**:
- Government policy changes and delays
- Infrastructure setup (power, connectivity, etc.)
- Inter-departmental approvals
- Hardware procurement and procurement process

## Risk Assumptions & Mitigations

| Risk | Assumption | Mitigation |
|------|------------|------------|
| Scope Creep | Client will manage scope tightly | Formal change control process |
| Resource Attrition | 15% bench maintained | Replacement guarantee (30 days) |
| Timeline Delays | Client decisions on time | Governance escalation |
| Data Quality | Data is fit for purpose | Data quality assessment phase |
| Integration Complexity | APIs are documented | Integration testing earlier |
| Regulatory Changes | Stable regulatory environment | Regular regulatory monitoring |
| Security Breach | Jointly managed | Security incident response plan |
| Change Adoption | Client drives adoption | Change management program |

3. Any change in assumptions/exclusions requires formal amendment
